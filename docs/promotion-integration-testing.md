# 活動管理整合測試

## 新舊訂單分界

- 新程式建立的訂單會明確寫入 `promotionFlowVersion = 1`，即使當下沒有活動，也會保留「不符合活動」的結果，不追溯補活動。
- 舊訂單的版本欄位維持 NULL，不回填、不用日期推測、不因後台啟用活動而改流程。
- 舊訂單維持原商品尾款輸入、尾款連結、合併、信用卡重試及轉帳收款流程；不提供新活動報價／尾款優惠券功能。
- 新版訂單之間依新流程操作；舊版訂單之間沿用原流程；依使用者確認，本次暫不支援新舊跨版本合併。
- 新增 `0047_order_promotion_flow_version.sql`；若先前測試已套用 0046，重新執行專用腳本只會補上 0047，不修改既有訂單。

## 本次範圍（僅限版本 1 訂單）

- 全館自動「每滿額折抵」，以目前售價計算；折扣商品也參加。
- 一般訂單先扣活動，再以活動後商品金額判斷會員優惠券低消，再加運費。
- 客製訂金不扣活動、不使用優惠券。下單保存當時活動規則，填寫尚欠尾款時自動推算完整售價並計算折抵。
- 合併客製逐單報價、逐單算活動，再合計尾款；一般已付商品不重複計算。
- 活動可折尾款及運費至 0，不退訂金、不退現；優惠券仍只折剩餘商品尾款。
- 取消訂單沿用優惠券退回，不延長原期限。
- 不處理多活動疊加與部分退款。請安排不重疊的活動期間；本版只取一筆有效活動。

- `/admin/promotions`：名稱「活動整合測試」，每滿 1111 折 111、上限留空、啟用，期間涵蓋目前台灣時間。

## 先驗收舊單相容性

請使用套用 0047 前已存在、`promotionFlowVersion IS NULL` 的測試訂單。不要修改正式訂單做測試，也不要把舊單的 NULL 手動改成 1。

1. 開啟既有舊客製單：不應出現「設定客製總價／自動計算優惠」；產生尾款仍要求輸入商品尾款，原連結編號不變。
2. 選取兩筆舊單合併：維持原本允許的合併條件（包括原流程允許已有尾款連結的情況），不強制逐單最終報價；主單仍輸入合併商品尾款。
3. 原有尾款連結分別走信用卡重試、轉帳與零尾款配送；不得要求優惠券、活動資格或新報價。
4. 舊單的歷史信用卡交易回呼仍採原流程，既有編號及應付金額不重寫。
5. 後台啟用／停用活動：舊訂單與原尾款金額都不變。
6. 一筆舊單加一筆新單嘗試合併：明確拒絕跨版本合併，不改任何訂單或建立合併群組。
7. 舊單的取消與優惠券退回維持原規則。

## 再驗收新版的三條主要路徑

### A. 一般商品 + 活動 + 優惠券

1. 商品小計 2500：購物袋／結帳顯示活動折 222，活動後商品為 2278。
2. 滿 2000 折 100 可選；滿 2400 折 100 不可選，運費不影響低消。
3. 最終付款為 2178 + 原本應收運費；若兩件免運就為 2178。
4. 用測試轉帳或 sandbox 信用卡完成，核對訂單、後台、會員中心的活動列與優惠券列。
5. 取消訂單，原券退回；過期券仍顯示過期。

### B. 客製單保留活動，活動結束後報價

1. 活動中建立客製訂金單，確認訂金仍收 1000、活動尚未折抵、不提供訂金優惠券。
2. 完成訂金付款，訂單應為已付訂金。
3. 編輯／停用該活動；也可改活動截止時間至現在以前。
4. 後台按「產生尾款／配送連結」，在原本的提示框輸入尚欠客製尾款 **2333**（活動折抵前，不含已付訂金與運費）。
5. 系統自動加回已付訂金 1000，推算客製總價 3333，依原規則折 333，並直接產生連結。商品尾款折抵後為 2000；若宅配運費 130，應付 2130。
6. 優惠券低消以 3333 − 333 = 3000 判斷；若用滿 2000 折 100，應付 2030。
7. 完成尾款，確認已付與折抵紀錄。付款重試不再套用新活動，不再次扣訂金。

### C. 合併客製，逐單規則不同

1. 建立 A：有活動，訂金 1000；建立 B：無活動，訂金 1000。先完成兩筆訂金。
2. **先合併，再產生尾款連結**。已有尾款連結的訂單不能再合併，避免舊連結仍能付款。
3. 在主訂單按「產生尾款／配送連結」，依序輸入 A 尚欠尾款 500、B 尚欠尾款 1000；系統各自加回訂金 1000，推算客製總價 1500、2000。
4. A 折 111、B 折 0；應收商品尾款合計 1389。不得按合計 3500 重新算雙十一優惠。
5. 任一提示框取消或未提供全部客製單的尾款，不產生連結；API 收到不完整的逐單資料也應拒絕，不保存部分報價。
6. 核對合併免運覆寫、付款結果與逐單活動明細。

## 邊界／防誤操作清單

| 情境 | 預期 |
|---|---|
| 小計 1110 / 1111 / 2221 / 2222 / 3333 | 折 0 / 111 / 111 / 222 / 333 |
| 折抵上限 250，小計 3333 | 折 250；不再提示下一階 |
| 活動尚未開始、已結束、停用 | 新訂單不適用；已保留客製規則不變 |
| 活動結束時刻 | 使用不含結束時刻的期間 `[startsAt, endsAt)` |
| 結帳畫面開著時修改活動／價格 | server 金額不一致時要求重新整理，不直接付款 |
| 客製總價 1111、訂金 1000、運費 60 | 商品尾款 111、活動 111，仍收運費 60 |
| 客製總價 1111、訂金 1100、運費 60 | 尾款 11 + 運費 60，實際折 71，結清 0；不退回其他 40 |
| 上例改運費 130 | 應付 30 |
| 0 元尾款配送 | 填配送資料後結清，不建立金流交易 |
| 尚欠尾款輸入負數或非整數 | 阻擋；輸入 0 仍允許產生配送連結 |
| 未進入付款流程前修改尾款 | 重新按產生連結並輸入尚欠尾款，沿用原連結編號，原活動規則與新尾款於同一交易更新 |
| 已有信用卡交易／已產生轉帳金額／轉帳待確認／已付款 | 阻擋重新報價或重設尾款，避免舊金額仍可支付 |
| 同一尾款信用卡重試 | 使用獨立付款編號，沿用同一優惠券，不能同時切轉帳 |
| 已開始無券信用卡付款後再加券 | 阻擋，避免舊金額付款與新折抵混用 |
| 未登入或非原訂購會員加券 | 拒絕；已保留券的既有付款連結仍可沿用 |
| 優惠券折抵大於剩餘商品尾款 | 只折剩餘商品尾款，不退現、不折運費 |
| 取消客製／合併訂單 | 沿用原本群組取消與優惠券退回；舊尾款不可再付款 |
| 已打折商品、無活動舊訂單 | 活動以售價算；舊訂單不追溯補活動 |

額外白水晶加購沿用既有尾款加購流程，不改已鎖定客製報價的活動基準。

## 補充：同筆訂單含一般商品與客製訂金

- 管理員仍按「產生尾款／配送連結」，輸入活動折抵前的「尚欠客製尾款」，不含已付訂金、首單一般商品與運費；不再提供額外的設定總價按鈕。
- 系統先加回已付客製訂金，再自動加計首單一般商品，活動門檻為「尚欠客製尾款＋客製訂金＋首單一般商品」。首單含客製時未先折活動，因此這裡集中在尾款折抵一次。
- 商品尾款本金仍是「客製商品總價−已付客製訂金」，不重收一般商品。
- 優惠券低消以整筆商品扣活動後金額判斷，實際券折抵仍不超過剩餘商品尾款。
- 例：一般商品 2500、客製總價 2000、訂金 500，活動門檻 4500，折 444；尾款 1500−444＝1056。若再用 100 元券、運費 130，應付 1086。
- 已保存但缺少首單商品金額的舊報價不會被靜默改價。尚未進入付款流程者需重新按產生連結並輸入尚欠尾款，才保存修正後的優惠。已進入付款流程或已付款者需逐單確認，不自動重算。

## 尾款輸入流程（後續確認）

單筆與無活動情況都保留原操作：按產生連結 → 提示框輸入尚欠客製尾款 → 自動計算優惠並產生連結。輸入的是活動折抵前本金，不是含訂金的總價，也不是手動扣完優惠的金額。合併單仍依先前確認的逐單活動規則，從同一顆按鈕依序輸入各單尚欠尾款後，一次產生合併連結。

後端在同一 transaction 保存報價、活動明細與尾款連結；取消提示框不送出請求，不完整或不合法的逐單金額不會留下部分報價。既有已進入付款流程的金額仍受保護，舊版本訂單仍沿用原流程。

## 前台活動文案

- 購物袋／結帳：保留活動名稱、每滿折抵規則、預估優惠與下一階差額；不列活動期間與優惠券計算規則。
- 客製尚未報價：只說「活動優惠將於尾款折抵。」
- 訂單／尾款活動摘要：只列活動名稱與優惠金額；沒有活動或沒有折抵時不額外顯示活動框。
- 客人不需要看到下單資格保存、規則快照、計算基準、優惠券保留／重試等內部流程。
- 付款小計、運費、優惠券實際折抵與應付總額仍完整保留；用券區只保留每單一張與限折抵商品的必要資訊。
- 後台仍可看到客製商品金額、訂金、其他已付商品與活動適用金額，便於核對，無須另外設定總價。
